# 常见错误码

> 本章节列出 Wwise Authoring API (WAAPI) 中可能遇到的所有错误码，包括 JSON-RPC 2.0 标准错误码和 WAAPI/Wwise 特有的错误。

---

## 1. 错误响应格式

WAAPI 基于 JSON-RPC 2.0 协议。当调用失败时，服务器返回的错误响应格式如下：

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32602,
    "message": "Invalid params",
    "data": {
      "details": "Missing required parameter: 'parent'"
    }
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `error.code` | integer | 错误码（负数表示错误） |
| `error.message` | string | 简短的错误描述 |
| `error.data` | object（可选） | 附加的错误详情，具体内容因错误类型而异 |

---

## 2. JSON-RPC 2.0 标准错误码

以下为 JSON-RPC 2.0 规范定义的标准错误码，WAAPI 完全遵循这些规范。

| 错误码 | 名称 | 含义 | 常见原因 | 解决方案 |
|--------|------|------|----------|----------|
| **-32700** | Parse error | 服务器接收到无效的 JSON | 请求体中包含语法错误的 JSON（如缺少引号、多余的逗号、未转义的特殊字符） | 使用 JSON 校验工具检查请求体格式；确保所有字符串用双引号包裹 |
| **-32600** | Invalid Request | 发送的 JSON 不是有效的 Request 对象 | 缺少必要的 JSON-RPC 字段（如 `jsonrpc`、`method`）；`id` 字段类型不正确 | 确保请求包含 `jsonrpc: "2.0"`、`method` 和 `id`（或 `id: null` 用于通知） |
| **-32601** | Method not found | 请求的方法不存在或不可用 | 1. 函数 URI 拼写错误<br>2. 请求的函数在当前 Wwise 版本中不存在<br>3. 使用了 HTTP POST 访问仅支持 WAMP 订阅的功能（如 Pub/Sub） | 1. 通过 `ak.wwise.waapi.getFunctions` 查询可用函数列表<br>2. 确认函数名拼写<br>3. 检查协议兼容性（参见下表） |
| **-32602** | Invalid params | 方法参数无效 | 1. 缺少必需参数<br>2. 参数类型不匹配<br>3. 参数值超出允许范围<br>4. 参数格式不符合 Schema 定义 | 1. 通过 `ak.wwise.waapi.getSchema` 查询函数参数 Schema<br>2. 检查每个参数的类型和格式<br>3. 确认所有 `*` 标记的必需参数已提供 |
| **-32603** | Internal error | 内部 JSON-RPC 错误 | 服务器端发生意外异常（非用户参数导致） | 检查 Wwise 的 General 日志获取更多详情；尝试重新连接 |

### HTTP POST 协议限制

以下 WAAPI 功能在 HTTP POST 协议中**不可用**（会返回 `-32601` Method not found）：

| 功能 | HTTP POST 支持情况 |
|------|-------------------|
| Remote Procedure Calls（远程过程调用） | ✅ 支持 |
| Publish & Subscribe（发布与订阅） | ❌ 不支持 |
| 获取订阅通知 | ❌ 不支持（仅 WAMP 支持） |

## 3. WAAPI 特有错误

以下错误是在 WAAPI 操作过程中常见的 Wwise 层面的错误。这些错误通过 `error.data` 字段提供额外的上下文信息。

### 3.1 对象相关错误

| 错误场景 | 典型错误码 | 说明 | 常见原因 | 解决方案 |
|----------|-----------|------|----------|----------|
| **对象不存在** | `-32602` | 指定的对象 ID（GUID）或路径在项目中不存在 | 1. 对象已被删除或移动<br>2. GUID 复制错误<br>3. 项目未加载 | 1. 使用 `ak.wwise.core.object.get` 查询确认对象是否存在<br>2. 使用 WAQL 查询搜索对象名称<br>3. 确认项目已正确加载 |
| **名称冲突** | `-32602` | 在相同父对象下创建同名对象 | 同一父对象下已存在同类型且同名的对象 | 使用不同的名称，或在重命名前检查 `ak.wwise.core.object.get` |
| **无效的对象类型** | `-32602` | 创建对象时指定了不存在的类型 | `type` 参数值不在 `ak.wwise.core.object.getTypes` 返回的列表中 | 使用 `ak.wwise.core.object.getTypes` 获取所有有效类型 |
| **父对象无效** | `-32602` | 指定的父对象不支持该类型的子对象 | Wwise 对象层次结构限制（如不能将 Sound 放在 Event 下） | 参考 [Wwise Objects Reference](https://www.audiokinetic.com/library/2024.1.14_9084/?source=SDK&id=wobjects_index.html) 了解对象层次关系 |
| **权限/只读对象** | `-32602` | 尝试修改只读属性或系统对象 | 尝试修改内置对象或受保护的属性 | 确认对象和属性支持修改；检查 `ak.wwise.core.object.isPropertyEnabled` |

### 3.2 参数校验错误

通过 `ak.wwise.debug.validateCall` 函数可以在 Debug 构建中验证参数和选项的有效性（官网未提供详细的参数级错误码列表，实际错误信息通过 `error.message` 和 `error.data.details` 返回）。

### 3.3 项目状态相关错误

| 错误场景 | 典型错误码 | 说明 |
|----------|-----------|------|
| **项目未加载** | `-32603` | 在项目未打开时调用了需要项目上下文的函数（如操作对象） |
| **项目正在加载中** | `-32603` | 项目正在加载过程中，暂时无法处理请求 |
| **模态对话框阻止** | 连接中断 | Wwise 弹出模态对话框时，WAAPI 服务器可能暂时不可用 |

### 3.4 协议级错误

| 错误场景 | 说明 |
|----------|------|
| **WAMP 会话超时** | WAMP 连接因长时间无活动而断开 |
| **连接数超限** | 达到最大连接数限制（WAMP 20 个，HTTP 20 个）时，新连接被拒绝 |
| **IP 未授权** | 默认仅允许 localhost（127.0.0.1 或 ::1）连接，远程 IP 需要在 User Preferences 中添加 |

## 4. error.data 字段解读

`error.data` 字段的内容取决于具体的错误类型，常见格式包括：

### 4.1 参数验证错误

```json
{
  "error": {
    "code": -32602,
    "message": "Invalid params",
    "data": {
      "details": "Missing required parameter: 'parent'"
    }
  }
}
```

`data.details` 提供人类可读的错误详情，指出具体哪个参数有问题。

### 4.2 音频导入错误

`ak.wwise.core.audio.import` 函数即使在处理过程中部分文件导入失败，也不会返回错误。导入过程中的问题会写入 Wwise 日志。需要使用 `ak.wwise.core.log.get` 检索日志来查看导入结果。

### 4.3 音频转换错误

`ak.wwise.core.audio.convert` 函数在发生错误时返回一个消息列表，每条消息包含严重级别：

```json
{
  "error": {
    "code": -32603,
    "message": "Conversion failed",
    "data": {
      "messages": [
        {"severity": "Error", "message": "Source file not found"}
      ]
    }
  }
}
```

## 5. 错误排查一般流程

1. **检查 JSON 格式**：确保请求体是有效的 JSON
2. **验证函数名**：通过 `ak.wwise.waapi.getFunctions` 确认函数存在且拼写正确
3. **验证参数 Schema**：通过 `ak.wwise.waapi.getSchema` 获取函数的完整参数定义
4. **检查 Wwise 状态**：使用 `ak.wwise.core.ping` 验证 WAAPI 可用性
5. **查看 Wwise 日志**：使用 `ak.wwise.core.log.get` 检索日志或检查 Wwise 的 General 日志标签页
6. **检查网络配置**：确认端口、IP 白名单、防火墙设置正确
