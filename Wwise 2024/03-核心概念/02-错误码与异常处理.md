# 02-错误码与异常处理

## JSON-RPC 2.0 标准错误码

WAAPI 使用 JSON-RPC 2.0 标准错误码体系。当请求处理出错时，响应中包含 `error` 对象。

### 标准错误码表

| 错误码 | 含义 | 说明 | 常见原因 |
|--------|------|------|---------|
| `-32700` | **Parse error** | 服务器收到无效的 JSON | JSON 格式错误（缺少引号、逗号、括号不匹配等） |
| `-32600` | **Invalid Request** | 发送的 JSON 不是有效的请求对象 | 缺少必需字段（`method`）或请求结构不正确 |
| `-32601` | **Method not found** | 方法不存在 | 函数 URI 拼写错误或 Wwise 版本不支持该函数 |
| `-32602` | **Invalid params** | 无效的方法参数 | 参数缺失、类型错误、值超出范围、格式不正确 |
| `-32603` | **Internal error** | JSON-RPC 内部错误 | Wwise 内部异常或未预期的运行时错误 |

### 标准错误响应示例

```json
{
    "id": 1,
    "jsonrpc": "2.0",
    "error": {
        "code": -32602,
        "message": "Invalid params",
        "data": "The parameter 'waql' is required"
    }
}
```

### 服务器端错误范围

JSON-RPC 2.0 规范保留以下范围供服务器端定义：
- **-32000 到 -32099**: 预留的服务器错误码范围

## WAAPI 特有错误

WAAPI 在标准 JSON-RPC 错误码基础上，通过 `error.data` 字段提供更具体的错误上下文信息。

### 常见 WAAPI 错误场景

| 错误场景 | 标准错误码 | data 字段常见内容 | 解决方案 |
|---------|-----------|-------------------|---------|
| **对象不存在** | `-32602` | 包含无效的 GUID 或路径信息 | 确认对象 GUID/Path 正确；对象可能已被删除 |
| **权限不足** | `-32603` | 操作被拒绝的原因 | 检查 Wwise 用户偏好设置中的安全配置 |
| **名称冲突** | `-32602` | 冲突的对象名称和位置 | 使用 `rename` 模式或指定唯一名称 |
| **平台无效** | `-32602` | 无效的平台名称或 GUID | 使用 `ak.wwise.core.object.get` 获取有效平台列表 |
| **类型不匹配** | `-32602` | 期望类型 vs 实际类型 | 确认操作适用于该对象类型，参考 Wwise Objects Reference |
| **引用无效** | `-32602` | 引用的目标对象不存在 | 确认被引用的对象存在且类型正确 |
| **参数值超出范围** | `-32602` | 有效范围 [min, max] | 确认参数值在文档规定的范围内 |
| **工作单元冲突** | `-32603` | 工作单元正在被修改 | 先保存或放弃其他修改，再重试 |

### 从 Functions 页面提取的错误相关函数

WAAPI 提供了日志功能用于调试错误：

| 函数 | 说明 |
|------|------|
| `ak.wwise.core.log.addItem` | 向 Wwise 日志添加条目（用于调试） |
| `ak.wwise.core.log.clear` | 清除日志 |
| `ak.wwise.core.log.get` | 获取当前日志内容 |
| `ak.wwise.core.ping` | 验证 WAAPI 连接状态 |
| `ak.wwise.debug.enableAsserts` | 启用断言 |
| `ak.wwise.debug.enableAutomationMode` | 启用自动化模式 |
| `ak.wwise.debug.testAssert` | 测试断言功能 |
| `ak.wwise.debug.testCrash` | 测试崩溃处理 |
| `ak.wwise.debug.validateCall` | 验证调用格式（待补充详细说明） |

## 错误响应中的 data 字段

`error.data` 字段是 WAAPI 错误处理的核心，提供比 `error.message` 更详细的上下文信息。

### data 字段常见格式

**参数错误：**
```json
{
    "error": {
        "code": -32602,
        "message": "Invalid params",
        "data": "Expected parameter 'object' of type 'string'"
    }
}
```

**对象不存在：**
```json
{
    "error": {
        "code": -32602,
        "message": "Invalid params",
        "data": "Object '{XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX}' not found"
    }
}
```

**名称冲突：**
```json
{
    "error": {
        "code": -32602,
        "message": "Invalid params",
        "data": "An object named 'MySound' already exists at '\\Actor-Mixer Hierarchy\\Default Work Unit\\'"
    }
}
```

## 重试策略建议

### 1. 瞬时错误重试

对于网络相关的瞬时错误，使用指数退避重试：

```python
import time

def call_with_retry(client, method, args, options=None, max_retries=3):
    for attempt in range(max_retries):
        try:
            return client.call(method, args, options=options)
        except Exception as e:
            if attempt == max_retries - 1:
                raise
            wait_time = 2 ** attempt  # 1s, 2s, 4s
            time.sleep(wait_time)
```

### 2. 参数错误不重试

`-32602 Invalid params` 表示请求参数有问题，重试不会解决，应直接修正参数后重新调用。

### 3. 名称冲突处理

创建对象时使用 `onNameConflict: "rename"` 模式自动处理名称冲突：

```json
{
    "object": "\\Actor-Mixer Hierarchy\\Default Work Unit",
    "type": "Sound",
    "name": "MySound",
    "onNameConflict": "rename"
}
```

### 4. 依赖对象验证

在设置引用前，先验证目标对象是否存在：

```python
# 验证 OutputBus 存在后再设置
result = client.call("ak.wwise.core.object.get", {
    "waql": "$ from type Bus where name = \"Master Audio Bus\"",
    "return": ["id"]
})
if result and result.get('return'):
    bus_id = result['return'][0]['id']
    # 现在安全地设置引用
    client.call("ak.wwise.core.object.setReference", {
        "object": sound_id,
        "reference": "OutputBus",
        "value": bus_id
    })
```

## 调试技巧

### 1. 使用 log 函数

在调试脚本中，使用 `ak.wwise.core.log.addItem` 记录上下文信息：

```json
{
    "id": 99,
    "jsonrpc": "2.0",
    "method": "ak.wwise.core.log.addItem",
    "params": {
        "channel": "WAAPIDebug",
        "message": "Processing object: {24979032-B170-43E3-A2E4-469E0193E2C3}",
        "severity": "Info"
    }
}
```

### 2. 使用 ak.wwise.waapi.getFunctions 验证可用函数

查询 Wwise 当前支持的所有函数，确认函数可用：

```json
{
    "id": 1,
    "jsonrpc": "2.0",
    "method": "ak.wwise.waapi.getFunctions",
    "params": {}
}
```

### 3. 使用 ak.wwise.waapi.getSchema 获取函数签名

获取特定函数的完整 schema，确认参数格式：

```json
{
    "id": 1,
    "jsonrpc": "2.0",
    "method": "ak.wwise.waapi.getSchema",
    "params": {
        "uri": "ak.wwise.core.object.set"
    }
}
```

### 4. 使用 ak.wwise.core.ping 检查连接状态

在批量操作前后 ping 确认连接正常：

```json
{
    "id": 1,
    "jsonrpc": "2.0",
    "method": "ak.wwise.core.ping",
    "params": {}
}
```

### 5. 分步调试复杂操作

对于 `ak.wwise.core.object.set` 的批量操作，如果出错，先拆分为单对象操作逐步排查。

### 6. Wwise 用户偏好设置

确保 WAAPI 已启用：
- 在 Wwise 中选择 **Project > User Preferences**（快捷键 Shift + U）
- 在 **Wwise Authoring API** 组中勾选 **Enable Wwise Authoring API**

### 7. 网络和安全配置

- 默认只允许 localhost 连接（127.0.0.1 或 ::1）
- 远程连接需在 User Preferences 的 **Allow connections from** 中添加 IP 地址
- 浏览器连接需在 **Allow browser connections from origins** 中添加源 URI
- 警告：使用 `*` 通配符不安全，不推荐

### 8. 监控 Wwise 日志

Wwise 的 "Logs" 视图也会输出 WAAPI 相关的错误和警告信息，是调试的重要辅助工具。
