# 连接与配置问题

> 本章节涵盖 WAMP/HTTP 连接失败、端口配置、防火墙、权限等常见连接问题的诊断和解决方法。所有信息来源于 Wwise 2024.1.14 官方文档。

---

## 1. WAMP 连接失败的常见原因

WAMP（Web Application Messaging Protocol）是 WAAPI 推荐使用的协议，通过 WebSocket（默认端口 8080）进行双向通信。以下是 WAMP 连接失败的最常见原因。

### 1.1 Wwise 未运行

**现象**：客户端无法建立 WebSocket 连接到 `ws://localhost:8080/waapi`

**原因**：WAAPI 服务器由 Wwise Authoring 应用程序托管。如果 Wwise 没有运行，WAAPI 服务器不存在。

**解决方案**：
1. 启动 Wwise Authoring 应用程序
2. 确认 WAAPI 已启用：**Project > User Preferences**（快捷键 `Shift+U`），在 **Wwise Authoring API** 组框中勾选 **Enable Wwise Authoring API**
3. 点击 **OK** 保存设置

> 注意：WAAPI 默认是启用的。如果您之前手动禁用了它，需要重新启用。

---

### 1.2 防火墙阻止

**现象**：客户端无法连接到 Wwise，尤其是远程连接时

**原因**：操作系统防火墙或网络防火墙阻止了对 WAAPI 端口（默认 8080 和 8090）的访问。

**解决方案**：
- **本地连接**：确保防火墙允许本地回环（127.0.0.1）访问 8080 和 8090 端口
- **远程连接**：在防火墙中为授权 IP 添加 8080（WAMP）和 8090（HTTP）端口的入站规则
- 官方建议：使用防火墙阻止未经授权的远程计算机访问这些端口，仅将可信主机添加到白名单中

> 来自官方文档：*"For greater security, we recommend you block remote computers from accessing those ports, by using a Firewall. If you wish to allow remote computers to access WAAPI, we recommend adding them in a white list, instead of allowing any remote connection."*

---

### 1.3 错误的 Realm

**现象**：WAMP 连接在认证阶段失败

**原因**：WAAPI 使用固定的 WAMP Realm 名称 `realm1`。如果客户端配置了不同的 realm，连接将被拒绝。

**解决方案**：
- 确保 WAMP 客户端在连接时指定正确的 realm：**`realm1`**
- 典型连接 URL：`ws://localhost:8080/waapi`，realm 必须为 `realm1`

---

### 1.4 IP 地址未授权

**现象**：远程计算机无法连接，即使 Wwise 正在运行且防火墙已配置

**原因**：**默认情况下，WAAPI 仅接受来自 localhost（127.0.0.1 或 ::1）的连接**。来自远程计算机的连接会被直接拒绝。

**解决方案**（来自官方文档）：
1. 在 Wwise 菜单中点击 **Project > User Preferences**
2. 在 **Allow connections from** 字段中添加远程主机的 IP 地址。例如：
   - IPv4 地址：`203.0.113.255`
   - IPv6 地址：`2001:db8::`
3. 点击 **OK**

> ⚠️ **警告**（来自官方文档）：*"You can add \* to allow connections from any IP address. But, this is insecure and, therefore, unrecommended."*

---

## 2. HTTP 连接失败的常见原因

WAAPI 同时提供 HTTP POST 接口（默认端口 8090），适用于不支持 WebSocket 的环境。

### 2.1 错误的端口

**现象**：HTTP POST 请求返回连接被拒绝（Connection Refused）

**原因**：
- WAMP 端口是 **8080**，HTTP 端口是 **8090**
- 使用 HTTP POST 时，URL 应为 `http://localhost:8090/waapi`

| 协议 | 默认端口 | 端点路径 | 连接 URL 示例 |
|------|---------|----------|--------------|
| WAMP (WebSocket) | 8080 | `/waapi` | `ws://localhost:8080/waapi` |
| HTTP POST | 8090 | `/waapi` | `http://localhost:8090/waapi` |

### 2.2 CORS 问题（浏览器场景）

**现象**：在浏览器中使用 JavaScript 调用 WAAPI 时，请求被浏览器阻止，控制台出现 CORS 错误

**原因**：WAAPI 内置了跨站脚本（Cross-Site Scripting）安全层。默认情况下，WAAPI 仅接受以下来源的浏览器连接：
- 本地软件（非浏览器环境）
- 从本地文件系统打开的 HTML 文件

从远程 web 服务器加载的网页调用 WAAPI 会因安全策略而失败。

**解决方案**（来自官方文档）：
1. 在 Wwise 菜单中点击 **Project > User Preferences**
2. 在 **Allow browser connections from origins** 字段中添加 web 服务器的 URI。例如：
   - 默认端口 80：`http://www.myhost.com`
   - 自定义端口 1234：`http://www.myhost.com:1234`
3. 点击 **OK**

> ⚠️ **警告**（来自官方文档）：*"You can add \* to allow connections from webpages of any origin. But, this is insecure and, therefore, unrecommended."*

> 📝 **注意**（来自官方文档）：*"If you are connecting to WAAPI through a browser, both the IP address and origin of the web server must be added for the connection to be allowed."* 即浏览器场景下，**IP 地址**和**来源 origin** 都必须添加到白名单中。

## 3. 模态对话框导致 WAAPI 不可用

**现象**：WAAPI 请求突然超时或无响应

**原因**：当 Wwise 弹出模态对话框时（如项目迁移确认、EULA 接受、错误消息框等），WAAPI 服务器可能暂时停止处理请求。

**解决方案**：
1. 使用 `ak.wwise.debug.enableAutomationMode` 启用自动化模式，减少消息框和对话框的弹出：
   ```json
   {
     "method": "ak.wwise.debug.enableAutomationMode",
     "params": {"enable": true}
   }
   ```
   启用自动化模式后，以下对话框将被静默处理：
   - 项目迁移确认
   - 项目加载日志
   - EULA 接受
   - 项目许可证显示
   - 通用消息框

2. 实现请求重试机制和超时处理
3. 定期通过 `ak.wwise.core.ping` 检测 WAAPI 可用性

## 4. 最大连接数限制

**现象**：新客户端无法连接，现有连接可能被拒绝

**原因**：WAAPI 有最大并发连接数限制：

| 协议 | 最大连接数 |
|------|-----------|
| WAMP | **20** |
| HTTP POST | **20** |

> 来自官方文档：*"WAAPI supports usage from multiple connections at once. The current maximum number of active connections to WAAPI is 20 for WAMP, with another 20 for HTTP POST."*

**解决方案**：
- 检查是否有客户端未正确释放连接
- 释放不再使用的 WAMP session
- 对于 WAMP 连接，使用完 session 后确保发送 `Goodbye` 消息正确关闭
- 在连接池模式下，重复使用已有的连接而不是创建新连接

## 5. Mac 平台路径问题

**现象**：在 Mac 上使用 WAAPI 操作文件（如加载项目、导入音频）时路径无效

**原因**：WAAPI 使用 Windows 风格的路径格式。

| Mac 路径 | WAAPI 路径 |
|----------|-----------|
| 根目录 `/` | `Z:\` |
| 用户主目录 `/Users/xxx/` | `Y:\` |
| 示例 `/Volumes/path/to/MyProject.wproj` | `Z:\Volumes\path\to\MyProject.wproj` |

**解决方案**（来自官方文档）：
- 将 Mac 绝对路径中的 `/` 替换为 `\`
- 将根目录 `/` 映射为驱动器 `Z:`
- 如有疑问，参考 Wwise 最近项目列表中显示的路径格式

## 6. 如何验证 WAAPI 状态

### 6.1 使用 `ak.wwise.core.ping`

这是验证 WAAPI 是否可用的最直接方法。该函数无需参数，返回空对象 `{}` 即表示成功。

**WAMP (JavaScript) 示例**：
```javascript
const connection = new autobahn.Connection({
  url: 'ws://127.0.0.1:8080/waapi',
  realm: 'realm1'
});

connection.onopen = async (session) => {
  try {
    await session.call('ak.wwise.core.ping');
    console.log('WAAPI is available');
  } catch (err) {
    console.error('WAAPI is not available:', err);
  }
};

connection.open();
```

**HTTP POST 示例**：
```bash
curl -X POST http://localhost:8090/waapi \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"ak.wwise.core.ping"}'
```
成功响应：
```json
{"jsonrpc":"2.0","id":1,"result":{}}
```

### 6.2 使用 `ak.wwise.core.getInfo`

获取 Wwise 的详细信息，包括版本号、进程 ID、安装路径等：

```bash
curl -X POST http://localhost:8090/waapi \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"ak.wwise.core.getInfo"}'
```

该函数返回的信息包括：`sessionId`、`apiVersion`、`displayName`、`branch`、`copyright`、`version`（含 year/major/minor/build/nickname/schema）、`configuration`、`platform`、`isCommandLine`、`processId`、`processPath`、`directories` 等。

## 7. 快速排查清单

按以下顺序逐项检查：

| 步骤 | 检查项 | 操作 |
|------|--------|------|
| 1 | Wwise 是否运行？ | 启动 Wwise Authoring 应用程序 |
| 2 | WAAPI 是否启用？ | Project > User Preferences > Enable Wwise Authoring API |
| 3 | 是否使用正确的端口？ | WAMP → 8080，HTTP → 8090 |
| 4 | 是否使用正确的 Realm？ | WAMP 必须使用 `realm1` |
| 5 | 是否从 localhost 连接？ | 本地测试：使用 127.0.0.1；远程连接需添加 IP 到白名单 |
| 6 | 防火墙是否阻止？ | 检查防火墙规则，允许 8080 和 8090 端口 |
| 7 | 浏览器连接是否配置了 origin？ | 在 User Preferences 中添加 origin URI |
| 8 | 连接数是否超限？ | 关闭不用的连接（WAMP 20 上限，HTTP 20 上限） |
| 9 | Wwise 是否有模态对话框弹出？ | 启用自动化模式减少对话框 |
