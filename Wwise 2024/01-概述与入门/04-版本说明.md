# 04-版本说明

> 本章节基于 Wwise 2024.1 版本的 *New Features Overview 2024.1* 和 *Important Migration Notes 2024.1* 官方文档整理。

## 2024.1 版本概览

Wwise 2024.1 专注于改进音频创作工作流程的基础方面。实时连接改进（Live Media Transfer + 扩展的 Live Editing）提供了不间断的工作流。主要变更涵盖：

- **用户体验**：Live Media Transfer、扩展的 Live Editing、编辑器改进（Primary Editor、Contents Editor、Property Editor）
- **集成**：Unity Auto-Defined SoundBanks（支持 Addressables）、Unreal Packaging
- **空间音频**：ADM 支持（实验性）、反射改进与参数平滑（实验性）
- **SDK**：重构 Converted File Cache、新内存分配器（AkMemoryArena）
- **WAAPI**：新增 Blend Container 访问器
- **平台支持**：Apple VisionOS、OpenHarmony (OHOS)

## WAAPI 相关变更

### 新增的命名空间/函数

以下 Blend Container 相关的访问器在 2024.1 中新增：

| 函数 | 描述 |
|------|------|
| `ak.wwise.core.blendContainer.addTrack` | 添加 Blend Track |
| `ak.wwise.core.blendContainer.addAssignment` | 添加 Blend Container 子对象分配 |
| `ak.wwise.core.blendContainer.removeAssignment` | 移除 Blend Container 子对象分配 |
| `ak.wwise.core.blendContainer.getAssignments` | 获取 Blend Container 子对象分配 |

### 废弃的 API

以下 API 在 2024.1 中发生了废弃/变更：

#### 1. ak.wwise.console → ak.wwise.ui.project

原 `ak.wwise.console.project.*` 命名空间下的函数现已迁移至 `ak.wwise.ui.project.*`：

| 旧 API | 新 API |
|--------|--------|
| `ak.wwise.console.project.close` | `ak.wwise.ui.project.close` |
| `ak.wwise.console.project.create` | `ak.wwise.ui.project.create` |
| `ak.wwise.console.project.open` | `ak.wwise.ui.project.open` |

> ⚠️ 旧命名空间 `ak.wwise.console.*` 仍存在于 2024.1.14 文档中（可能为向后兼容），但强烈建议迁移到 `ak.wwise.ui.project.*`。

#### 2. ak.wwise.core.profiler.enableProfilerData 数据类型变更

`ak.wwise.core.profiler.enableProfilerData` 函数不再接受 `preparedEvents` 作为有效的数据类型。已更名为 **`preparedObjects`**。

新的数据类型支持：
- 使用 `AK::SoundEngine::PrepareEvent` 准备的 Events
- 使用 `AK::SoundEngine::PrepareBus` 准备的 Busses

#### 3. ak.wwise.waapi.getFunctions / getTopics 反射变更

`ak.wwise.waapi.getFunctions` 和 `ak.wwise.waapi.getTopics` 现在**仅返回当前模式下支持的函数或主题**，具体取决于调用是来自 Console 模式还是 UI 模式。

#### 4. ak.wwise.ui.captureScreen 参数变更

`ak.wwise.ui.captureScreen` 函数之前使用**显示名称（title）** 作为参数来标识视图，现在使用**唯一 ID 名称（unique ID name）**。

> 📖 参见 *Wwise Authoring View Identifiers* 获取所有可用视图名称的列表。

## 其他重要的迁移注意事项

### 1. XMA 编解码器已移除

- XMA 编解码器支持已从 Wwise 中**移除**
- 使用 XMA 格式的现有 Wwise 项目将**自动修改为使用 Vorbis**
- 旧媒体资源必须重新转换为兼容的软件编解码器才能正常工作

### 2. 2021.1 之前的旧版 Authoring Plug-in API 已移除

- 在 2023.1 中标记为弃用的旧版 Authoring Plug-in API **已在 2024.1 中移除**
- 如需将插件移植到 2021.1 引入的新 API，请参见官方文档 *Migrating a pre-2021.1 Authoring Plug-in*

### 3. IAkLowLevelIOHook::BatchCancel 已移除

- `IAkLowLevelIOHook::BatchCancel` 已从低级别 I/O 接口中移除
- 如果项目使用自定义 `IAkLowLevelIOHook` 实现，需删除 `BatchCancel` 函数覆写
- 如果使用 Wwise SDK 提供的示例实现，无需调整

### 4. 内存管理器集成变更

新的 `AkMemoryArena` 是默认内存分配器，部分初始化设置和内存系统回调已更改：

- `AkMemSettings::uMemAllocationSizeLimit` **已移除**。现对每个 Arena 有单独的 `AkMemoryArenaSettings::uMemReservedLimit` 值
- 以下分配/释放回调已移除，改用 `AkMemoryArenaSettings::fnMemAllocSpan` 和 `fnMemFreeSpan`：
  - `AkMemSettings::pfAllocVM`
  - `AkMemSettings::pfFreeVM`
  - `AkMemSettings::pfAllocDevice`
  - `AkMemSettings::pfFreeDevice`
- `AkMemSettings::bEnableSeparateDeviceHeap` **已移除**。如需禁用 Device AkMemoryArena，将 `fnMemAllocSpan` 设为 `nullptr`
- 以下 rpmalloc 架构专属设置已移除：
  - `AkMemSettings::uVMPageSize`
  - `AkMemSettings::uDevicePageSize`
  - `AkMemSettings::uMaxThreadLocalHeapAllocSize`
  - `AkMemSettings::uVMSpanCount`
  - `AkMemSettings::uDeviceSpanCount`

函数也相应重命名：
- `AKPLATFORM::AllocVM` → `AKPLATFORM::AllocSpan`
- `AKPLATFORM::FreeVM` → `AKPLATFORM::FreeSpan`
- `AKPLATFORM::AllocDeviceVM` → `AKPLATFORM::AllocDeviceSpan`
- `AKPLATFORM::FreeDeviceVM` → `AKPLATFORM::FreeDeviceSpan`

### 5. AK::SoundEngine::SetSpeakerAngles API 变更

- `in_fHeightAngle` 参数（定义高度层角度）现在**默认为 30 度**
- **禁止**为该值传递 0，即使当前扬声器配置没有高度声道

### 6. 制表符分隔导入的属性名变更

以下属性已在 2024.1 中重命名。如果在制表符分隔导入文件中使用这些属性，必须相应更改：

| 旧名称 | 新名称 |
|--------|--------|
| Enable Diffraction | Diffraction and Transmission |
| Enable Envelope | Enable Envelope Tracking |
| Global Or Per Object | Scope |
| Grid Frequency Preset | Grid Frequency |
| Grid Offset Preset | Grid Offset |
| Is Looping Enabled | Loop |
| Is Looping Infinite | Loop Infinite |
| Is Streaming Enabled | Stream |
| MIDI tracking root note | MIDI Note Tracking Root |
| Output Bus High-pass Filter | Output Bus HPF |
| Output Bus Low-pass Filter | Output Bus LPF |
| Override Parent MIDI Target | Override MIDI Target |
| Random or Sequence | Play Type |
| Step or Continuous | Play Mode |
| Switch/State | Default Switch/State |
| Use Priority Distance Factor | Use Offset Priority |
| User Auxiliary Send 0 | User-Defined Auxiliary Send 0 |
| User Auxiliary Send 1 | User-Defined Auxiliary Send 1 |
| User Auxiliary Send 2 | User-Defined Auxiliary Send 2 |
| User Auxiliary Send 3 | User-Defined Auxiliary Send 3 |
| Virtual voice behavior | When Limit is Reached |
| Voice High-pass Filter | Voice HPF |
| Voice Low-pass Filter | Voice LPF |

> ℹ️ 属性名 `When Limit is Reached` 仅适用于属性 ID `OverLimitBehavior`，不适用于 `BelowThresholdBehavior`。

## 平台支持变更

2024.1 新增以下平台支持：

- **Apple VisionOS**
- **OpenHarmony（OHOS）**

此外，WebGL 平台的实验性支持已改进：
- 为不使用 Unity 的游戏集成者添加了多线程支持
- Unity 2023.x 现已支持（Unity 2022.x 不再支持）

## 插件变更

Motion 插件（Windows）已更新为支持 **GameInput API**：
- 允许设计师在 Wwise Authoring 中试听 Xbox 控制器 Impulse Trigger 的行为
- 允许在支持的 Windows 游戏中使用 Impulse Triggers
- **移除**了 DirectInput 支持及部分相关 API

## 从旧版本迁移的注意事项

1. **检查 WAAPI 调用中是否使用了 `preparedEvents`** 数据类型，需迁移到 `preparedObjects`
2. **检查 `ak.wwise.console.*` 命名空间的使用**，迁移到 `ak.wwise.ui.project.*`
3. **检查 `ak.wwise.ui.captureScreen` 调用**，将显示名称参数替换为视图的 ID 名称
4. **检查制表符分隔导入文件**，更新旧属性名为新名称
5. **检查自定义 I/O Hook 实现**，移除 `BatchCancel` 方法
6. **检查内存管理器初始化代码**，适配新的 `AkMemoryArena` 架构
7. **如果使用 XMA 编解码器**，项目将自动迁移到 Vorbis，需重新转换媒体资源
8. **如果使用旧版 Authoring Plug-in API**（2021.1 之前），需要迁移到新 API
9. **检查 `AK::SoundEngine::SetSpeakerAngles`**，确保不再传递 0 作为高度层角度
